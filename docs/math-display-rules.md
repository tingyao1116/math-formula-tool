# 數學顯示規則（無限練習）

本文件作為本專案新增/修改題型時的統一格式規範。  
原則：**先正確，再最簡，再易讀**。

## 1) 係數 1 的省略
- `1x` 一律顯示為 `x`。
- `1x^2` 一律顯示為 `x^2`。
- `-1x` 顯示為 `-x`，`-1x^2` 顯示為 `-x^2`。

## 2) 負號與減負數寫法
- 不允許出現連續減號：`x--y`。
- 必須寫成：`x-(-y)`。
- 同理，其他類似位置都遵守此規則（如常數項、代入後算式）。

## 3) 分數一律最簡
- 分數要約成最簡分數（約分到互質）。
- 若可化為整數，直接顯示整數。
- 例：`6/8 -> 3/4`，`10/5 -> 2`。

## 4) 比例一律最簡整數比
- 比例 `a:b` 需先同乘/同除去掉小數與分母，再約成互質整數比。
- 例：`0.5:1.2 -> 5:12`，`6:8 -> 3:4`。

## 5) 根式一律最簡根式
- `\sqrt{n}` 若可提出平方因數，必須提出。
- 例：`\sqrt{48} -> 4\sqrt{3}`，`\sqrt{220} -> 2\sqrt{55}`。
- 係數若為 1，省略成 `\sqrt{m}`。

## 6) 分母有根號時要有理化
- 最終答案若分母含根號，需完成有理化分母。
- 單根號分母與雙項分母（共軛）都適用。

## 7) 答案呈現層次
- `簡答`：優先給最終最簡結果。
- `過程`：若題型需要，過程可保留中間步驟，但最後一行必須符合本規範（最簡分數、最簡根式、已有理化）。

## 8) 題幹與解答分工
- 題幹只放原題，不放技巧提示（例如換元 `t=...`）。
- 技巧（換元、配方、判別式等）放在答案過程中。

---

實作建議（程式端）：
- 優先用共用格式化函式處理：
  - `formatCoeffTerm(coeff, variable, power)`
  - `formatSubtraction(left, right)`（避免 `x--y`）
  - `reduceFraction()`
  - `formatFraction(n, d)`
  - `simplifyRadical()` / `formatRadical()`
  - `rationalizeDenominator()`
  - `formatRatio(a, b)`
- 新題型上線前，至少抽查：
  - 係數 1、省略是否正確
  - 是否有 `--`
  - 分數/比例/根式是否最簡

## 9) 目前 formatter 實際位置（修正）

這些 formatter 目前**不是**集中放在 `data/formula-practice.js`（該檔現在是主控／包裝層，不含這些函式），而是各自複製在 `data/practice-generators/*.js` 每個檔案內部（各檔是獨立 IIFE，互不共用）：

- `gcdInt`：`e4.js`、`e5.js`、`j1.js`–`j5.js`、`s1.js`–`s4.js`
- `reduceFraction` / `formatFraction`：`e5.js`、`j1.js`–`j5.js`、`s1.js`–`s4.js`
- `simplifyRadical` / `formatRadical`：`j3.js`、`j4.js`、`s1.js`–`s3.js`
- `formatCoeffTerm`：`j2.js`、`j3.js`
- `formatSubtraction`：`j3.js`

也就是說：

- 涵蓋並不完整，`e6.js`、`j6.js`、`s5.js` 目前沒有這些函式的本地副本。
- 同一個函式在不同檔案裡是各自貼上的複本，不是引用同一份程式碼；改一份不會同步到其他檔案。
- 新增或修改題型時，先確認你要編輯的那個 `data/practice-generators/<章碼>.js` 檔裡有沒有這些函式；沒有的話，先從既有檔案（例如 `j3.js`）複製一份對應函式進來，再呼叫，不要每次都重寫一套邏輯。
- 若之後要做「真正共用」，可考慮抽成獨立檔案讓所有 generator 檔載入，但目前現況就是分散複製，文件與實作要先對齊，不要照抄舊的「集中在 formula-practice.js」說法。
