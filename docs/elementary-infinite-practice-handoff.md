# 國小無限練習交接規則

本文件供新對話繼續製作國小無限練習使用。開始工作前，請先閱讀：

1. `AGENTS.md`
2. 本文件
3. `docs/new-thread-import-rules.md`

## 一、目前工作範圍與順序

依下列順序逐章完成，不要同時大範圍修改：

1. 檢查並完成 `e4-2-8簡化計算`
3. 依序製作 `e4-1-1` 到 `e4-1-10`


每次開始一章時，先搜尋現有章節資料、生成函數與題型 ID。若已有部分成果，應接續完成，不可新增重複 ID 或重複生成函數。

## 二、新對話可以直接貼的啟動指令

```text
請先閱讀 AGENTS.md、docs/elementary-infinite-practice-handoff.md 與
docs/new-thread-import-rules.md。

每一章都要先判斷適合的大類與小類，合併重複題型，移除只有大方向、
無法形成參數化題目的內容。判斷完成後直接實作，不必等我再次確認。
不可修改無關章節。
```

新對話不會自動取得舊對話中的圖片附件。處理新章節時，仍需附上該章截圖；建議一次只附一章，避免題型混在一起。

## 三、無限練習的定義

無限練習不是固定題庫隨機換順序，而是：

- 計算方法或解題結構固定。
- 題目中的數值、物件、單位、敘述條件能合理變化。
- 每次生成能產生新的有效題目。
- 參數受到限制，答案符合該年級程度且可清楚呈現。

禁止只建立數題固定字串，再用亂數抽題。每個小類都必須有實際參數生成邏輯。

## 四、每章的整理方式

1. 先閱讀截圖，列出可形成穩定計算方法的題型。
2. 將計算方法相同、只差情境敘述的題目合併為同一小類。
3. 依核心觀念分成適量大類，通常以 3 至 5 類為原則，但應以內容自然完整為準。
4. 每個大類下附掛數個明確小類。
5. 只有概念口號、教學方向、需依賴未提供圖形或無法形成完整題目的內容，不製作成無限練習，並在完成報告中列出。
6. 題目敘述、簡答、詳解與單位都要符合台灣國小數學用語。

## 五、生成函數必要格式

每個生成函數都必須直接回傳：

```js
return {
  questions,
  summaryAnswers,
  answers
};
```

要求：

- 三個陣列長度必須相同。
- `questions`：題目。
- `summaryAnswers`：可直接對答案的最終答案，包含必要單位。
- `answers`：完整詳解，清楚呈現算式、步驟與結論。
- 不可依賴 `deriveSummaryAnswerFromDetail` 從詳解猜測簡答。
- 不可出現 `undefined`、`NaN`、空答案或不合理的長小數。
- 分數、帶分數、小數與數學符號必須使用專案既有的安全格式。

## 六、參數化品質標準

- 每個小類至少要有多個可變參數，而不是只替換一個名字。
- 參數範圍需符合題意，例如整除、約分、單位換算或指定取概數時，要在生成階段保證條件成立。
- 生活題可變換人物、物品或場景，但不能只換名詞而保留完全固定數字。
- 避免連續生成高度重複的數值組合。
- 不使用「承上題」「如下圖」等缺少前文或圖形就無法作答的敘述。
- 題目若要求精確答案，就不要產生無限循環小數；若是概數題，必須明確指定取到哪一位。
- 所有答案都要重新由參數計算，不可把固定答案寫死。

## 七、教學內容標準

每個小類的說明應兼顧老師教學與學生自學：

- 先指出核心觀念，再說明計算規則。
- 詳解要呈現學生能模仿的步驟。
- 適時提醒常見錯誤，例如單位未統一、進位關係錯誤、把總量與部分量顛倒。
- 基礎題優先使用乾淨數值；進階題再加入跨單位、兩步驟或生活情境。
- 中文要自然完整，不可出現簡體字、亂碼或不合台灣教材習慣的用語。

## 八、資料來源與修改位置

主要檔案：

- 生成函數：`data/formula-practice.js`
- 永久資料來源：`program-db/database/practice-db.json`
- 自動產生的章節橋接檔：`data/formula-practice-assignments.js`

`data/formula-practice-assignments.js` 是生成結果，不應只修改此檔作為永久修正。題型資料應先寫入 `practice-db.json`，再執行：

```powershell
python .\program-db\scripts\sync_practice_bridge.py
```

不得修改與目前章節無關的資料或生成函數。

## 九、中文與編碼安全

過去的 `???` 多半是中文內容經過 PowerShell 管線或錯誤字元編碼後寫入檔案造成。

必須遵守：

- 手動修改優先使用 `apply_patch`。
- 不要把含中文的 PowerShell here-string 經由管線送入 `python -` 或 `node -`。
- 若需大量機械修改，建立實體 UTF-8 腳本檔後執行。
- 先檢查 `practice-db.json` 的中文正確，再同步橋接檔。
- 同步後再次檢查資料庫與橋接檔，不能只看網頁畫面。

## 十、每章完成後的驗證

至少執行：

```powershell
node --check .\data\formula-practice.js
node --check .\data\formula-practice-assignments.js
python -m json.tool .\program-db\database\practice-db.json
```

另外必須：

1. 搜尋本章資料是否出現 `???`、`�`、`undefined` 或 `NaN`。
2. 確認本章所有題型 ID 唯一。
3. 確認每個生成函數都回傳 `questions`、`summaryAnswers`、`answers`。
4. 逐一呼叫本章每個小類，至少抽樣多次。
5. 檢查三個輸出陣列長度一致。
6. 檢查題目、簡答、詳解與單位一致。
7. 在無限練習頁確認章節、大類與小類附掛位置正確。

## 十一、完成回報格式

完成一章後，簡要回報：

- 新增了幾個大類、幾個小類。
- 合併了哪些重複題型。
- 哪些截圖內容未製作，以及不適合製作的原因。
- 執行過哪些驗證。
- 是否仍有待處理問題。
