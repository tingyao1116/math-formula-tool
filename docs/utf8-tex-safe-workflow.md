# UTF-8 與 TeX 安全流程

這份文件是給之後所有匯入、整理、同步腳本共用的規則。目標只有三件事：

1. 中文不能變成亂碼。
2. 錯字不能靠自動猜測或自動替換。
3. 數學式與英文字母要能穩定用 TeX 顯示。

## 為什麼會出現亂碼

最常見的原因不是前端，而是匯入流程把文字先讀壞，再寫進 `formula-db.json` 或其他 JSON。

高風險做法有這幾種：

1. `subprocess.run(..., text=True)` 但沒有指定 UTF-8。
2. `errors="replace"` 或其他會偷偷吞掉錯誤的解碼方式。
3. 把終端輸出的文字直接當正式內容來源。
4. 寫回資料庫前沒有檢查 `�`。

只要流程容許「讀壞也照寫」，就一定會逼人一直人工巡頁。

## 一律使用的安全做法

### 1. 讀寫文字檔

- 文字檔一律 `encoding="utf-8"`。
- JSON 一律 `ensure_ascii=False`。
- 不准使用 `errors="replace"`。
- 解碼失敗時直接報錯中止，不准自動替換。

### 2. 呼叫外部命令

- 不要用 `subprocess.run(..., text=True)` 直接吃系統預設編碼。
- 一律先抓 bytes，再用 UTF-8 嚴格解碼。
- 命令輸出只要出現 `�`，就視為失敗。
- Python 子程序一律帶 `PYTHONUTF8=1` 與 `PYTHONIOENCODING=utf-8`。

### 3. 寫回資料庫前

- 寫入前先檢查來源文字不能含 `�`。
- 寫入後再掃一次 `formula-db.json`、`question-db.json`。
- 只要發現 `�`，不准同步到前端 bridge 檔。

### 4. 內容規則

- 保留原文，不自行改寫句子。
- 中文照原稿，不要猜字、補字、換說法。
- 句內數學式與英文字母用 `$...$`。
- 只有真的必要的獨立公式才用 `$$...$$`。
- 如果內容是主頁摘要或章節大綱，優先用句內公式，不要把整頁做成一堆區塊公式。

## TeX 規則

### 句內公式

- `設 $x$ 為未知數`
- `把交點 $(x_0,y_0)$ 代入兩式`
- `首項是 $a_1$，公差是 $d$`
- `若 $x > 0$，則 $|x| = x$`

### 區塊公式

只有在下面情況才用 `$$...$$`：

1. 需要獨立置中呈現的公式。
2. 需要多步驟對齊的推導。
3. 單純句內顯示會太擠。

## 腳本規範

之後所有會碰資料庫或主頁文字的腳本，都應優先共用：

- [scripts/text_safety.py](C:/codex資料夾/數學公式使用工具/scripts/text_safety.py)

這個工具做的事：

1. 統一 UTF-8 讀寫。
2. 統一 UTF-8 子程序執行。
3. 發現 `�` 就直接停止。
4. 避免 Windows 預設 code page 偷偷介入。

## 驗證流程

每次匯入或同步後，至少做這些檢查：

1. 確認 JSON 可正常 parse。
2. 掃描是否有 `�`。
3. 掃描是否有明顯可疑片段，例如 `???`。
4. 再同步到前端 bridge。

如果任何一步失敗，就停止，不要硬寫。

